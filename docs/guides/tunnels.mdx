# Remote Tunnels

When your phone and laptop are on **different networks** (different WiFi,
cellular vs WiFi, hotel vs home), you need to expose the local signaling
and relay services to the internet. Two free options: **Cloudflare Tunnel**
or **ngrok**.

## Cloudflare Tunnel (recommended)

Cloudflare Quick Tunnels are free, require no account, and give you a
stable `*.trycloudflare.com` URL per run.

### Install

```bash
# macOS
brew install cloudflared

# Or download from:
# https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/
```

### Expose signaling + relay

```bash
# terminal 1 — the Crosslink stack
npm run stack    # signaling :8081, relay :8082

# terminal 2 — tunnel signaling
cloudflared tunnel --url tcp://localhost:8081
# → prints: https://abc-xyz.trycloudflare.com

# terminal 3 — tunnel relay
cloudflared tunnel --url tcp://localhost:8082
# → prints: https://def-uvw.trycloudflare.com
```

### Start your host

Convert the HTTPS URLs to WSS:

```bash
CROSSLINK_SIGNALING_URL=wss://abc-xyz.trycloudflare.com \
CROSSLINK_RELAY_URL=wss://def-uvw.trycloudflare.com \
npm run demo:echo
```

The QR code embeds these URLs automatically — the phone needs no config.

### Using the chat app

The chat app has built-in Cloudflare tunnel support:

```bash
npm run demo:chat
# On the web UI, click "Show QR" → select "Cloudflare" mode
```

Or start with the tunnel pre-configured:

```bash
CROSSLINK_TUNNEL=cloudflared npm run dev -w @crosslink/demo-chat
```

### Security

- **What Cloudflare sees**: Raw TCP bytes → ciphertext. Crosslink frames are
  encrypted end-to-end (XChaCha20-Poly1305), so the tunnel cannot read your
  messages, keys, or pairing data.
- **URL rotation**: Free-tier URLs change on restart. You must re-scan the QR
  after restarting. For stable URLs, connect a Cloudflare account (free) and
  use named tunnels.
- **Rate limiting**: Quick tunnels have soft limits. Named tunnels with an
  account have higher quotas.
- **Account required**: No — `cloudflared tunnel --url` works without any
  account or token.

## ngrok

ngrok provides TCP tunnels. Free tier requires an account.

### Install

```bash
# macOS
brew install ngrok

# Sign up at https://ngrok.com and get your authtoken
ngrok config add-authtoken <your-token>
```

### Expose signaling + relay

```bash
# terminal 1 — the Crosslink stack
npm run stack

# terminal 2 — tunnel signaling
ngrok tcp 8081
# → prints: Forwarding tcp://0.tcp.ngrok.io:12345:8081

# terminal 3 — tunnel relay
ngrok tcp 8082
# → prints: Forwarding tcp://0.tcp.ngrok.io:12346:8082
```

Copy the `wss://` URLs from each tunnel output.

### Start your host

```bash
CROSSLINK_SIGNALING_URL=wss://0.tcp.ngrok.io:12345 \
CROSSLINK_RELAY_URL=wss://0.tcp.ngrok.io:12346 \
npm run demo:echo
```

### Using the chat app

```bash
CROSSLINK_SIGNALING_URL=wss://0.tcp.ngrok.io:12345 \
CROSSLINK_RELAY_URL=wss://0.tcp.ngrok.io:12346 \
npm run demo:chat
```

Or use the built-in tunnel mode:

```bash
CROSSLINK_TUNNEL=ngrok npm run dev -w @crosslink/demo-chat
```

### Security

- **What ngrok sees**: Raw TCP bytes → ciphertext. Same E2E guarantees as
  Cloudflare — the tunnel operator cannot decrypt your traffic.
- **Authentication**: Free tier: anyone with the tunnel URL can reach your
  services. Paid tier ($8/mo): IP allowlists + OAuth.
- **Rate limiting**: Free tier has connection limits. Paid plan lifts most caps.
- **URL rotation**: Free tier URLs change on restart. Paid tier gets stable
  custom domains.

## Self-hosted VPS (production)

For permanent deployments, run on a VPS with a public IP:

```bash
# On your VPS
npm run build
export CROSSLINK_SIGNALING_TOKEN="$(openssl rand -hex 32)"
export CROSSLINK_RELAY_TOKEN="$(openssl rand -hex 32)"
npm run stack
```

Caddy config for automatic TLS:

```
signal.example.com {
  reverse_proxy /ws* 127.0.0.1:8081
  reverse_proxy *     127.0.0.1:8081
}
relay.example.com {
  reverse_proxy /ws*  127.0.0.1:8082
  reverse_proxy *     127.0.0.1:8082
}
```

See [Self-Hosting Guide](/self-hosting) for the full deployment walkthrough.

## Comparing options

| | Cloudflare Tunnel | ngrok | VPS |
|---|---|---|---|
| **Cost** | Free | Free (limited) / $8/mo | $5+/mo |
| **Setup time** | 2 minutes | 2 minutes | 30 minutes |
| **Stable URLs** | Account required | Paid only | Always |
| **Account needed** | No (quick) / Yes (named) | Yes (free) | No |
| **Best for** | Dev testing | Dev testing | Production |
| **E2E encrypted** | Yes | Yes | Yes |

## Security summary

All options maintain Crosslink's security guarantees:

1. **End-to-end encryption** — the tunnel sees only encrypted Crosslink frames.
   It cannot read messages, keys, or pairing data.
2. **Device authentication** — the CLX1 handshake requires an Ed25519 signature
   from a paired device. Discovering the tunnel URL doesn't help an attacker
   without a paired device's private key.
3. **Rate limiting** — both local dev services and VPS deployments have rate
   limits on channel creation and connection attempts.
4. **Dev tokens** — local services are closed by default (per-machine tokens
   in `.crosslink-data/`). Only processes on your machine can create relay
   channels or register as hosts.
