---
title: CLI Reference
description: Command-line interface for Crosslink
---

Crosslink has no installed CLI binary — these are `npm` scripts run from the root of the monorepo (or, for demos, from an example package).

## Services

### Start signaling and relay

```bash
npm run stack
```

Starts both services on localhost.

## Development

### Build all packages

```bash
npm run build
```

### Run tests

```bash
npm test
```

## Examples

### Run echo example

```bash
cd examples/echo-host
npm run dev
```

### Run notes example

```bash
cd examples/notes-host
npm run dev
```

### Run todo example

```bash
cd examples/todo-host
npm run dev
```

### Run an example with remote access

Several root-level scripts start a demo with `networkMode: "remote"` already configured — see [Remote Access](/guides/remote-access):

```bash
npm run demo:echo:remote
npm run demo:chat:remote
npm run demo:todo:remote
```

### Check remote-access readiness

```bash
npm run check:remote
```

## Environment variables

| Variable | Description | Default |
| --- | --- | --- |
| `PORT` | Signaling/relay service port | `8081` / `8082` |
| `HOST` | Signaling/relay bind address | `0.0.0.0` |
| `CROSSLINK_SIGNALING_URL` | Signaling URL (host SDK) | _(auto-discovered)_ |
| `CROSSLINK_RELAY_URL` | Relay URL (host SDK) | _(auto-discovered)_ |
| `CROSSLINK_SECRET_KEY` | Passphrase for encrypted storage | _(none)_ |
| `CROSSLINK_DATA_DIR` | Where the dev-token/stack config lives (`@crosslink/dev-tokens`). A host's own `storageDir` is a config field, not this. | `.crosslink-data` |

## Troubleshooting

### Port already in use

```bash
# Find what's using the port
lsof -i :8081

# Kill the process
kill <PID>
```

### Connection refused

```bash
# Check if services are running
curl http://127.0.0.1:8081/health
curl http://127.0.0.1:8082/health
```

### Module not found

```bash
# Ensure dependencies are installed
npm install

# Ensure you're using ESM
# package.json should have: "type": "module"
```
